项目定位

doit-gpui 是什么

doit 桌面的纯原生实现：以 gpui-kit（长桥开源、Zed GPUI 之上的 75+ 组件库，Apache-2.0，Longbridge Pro 商用验证）为 UI 底座，1:1 复刻现有 Tauri + Vue 版 doit-desktop 的全部界面、交互与数据契约。目标是一个不依赖 Chromium、单文件小体积、120 FPS 的桌面待办客户端。

UI 底座gpui-kit 0.10 · GPUI
语言 / 构建Rust · Cargo
目标平台macOS / Windows / Linux
数据契约Snapshot v2（与手机/桌面共用）
视觉基准本原型（doit-desktop 1:1）

为什么选择 gpui-kit

原生渲染，去掉浏览器内核

GPU 加速、原生手感、无 WebView 体积与内存开销；组件源自 shadcn 设计语言，与 doit 现有的圆角/令牌/浅色薄荷 + 深夜青灰审美高度契合。自带 Theme 系统（20+ 内置主题、亮暗切换、运行时换色）、图表、右键菜单、日历、虚拟列表、Dialog/Toast 等，覆盖桌面端绝大多数需求。

风险与边界（诚实说明）

① 无现成「热力图」组件，需自绘或用 BarChart 变通；② Vue→Rust 交互逻辑需重写（长按完成、父子树推导、三方合并）；③ gpui-kit 生态较年轻，文档与问答少于 Electron；④ 需 Rust 工具链与平台依赖。详见「能做到」与「路线图」页。

视觉还原度（本原型即验收基准）

令牌、圆角、间距、阴影、字号、亮暗主题均直接取自 doit-desktop 的 tokens.css / prototype.css，因此渲染目标与本原型肉眼一致。
设计层标注 ≈96% 视觉一致（图表为 GPUI 原生绘制，观感略有差异但配色/布局一致）。
原生组件直接实现 基础原语 + 自绘样式 无对应 / 需变通

需变通实现（效果接近）

完成热力图 — gpui-kit 图表无 Heatmap。方案 A：用 SvgElement/Canvas 自绘方格（推荐，灵活可控）；方案 B：用 BarChart 堆叠模拟。配色沿用 5 档 heat 令牌。

环形进度 / 勾选圈 — 用 SVG circle + stroke-dasharray 自绘，视觉与现有一致。

玻璃拟态顶栏 — GPUI 无 CSS backdrop-filter，用半透明纯色 + 顶栏阴影近似，肉眼差异很小。

需自行移植的核心逻辑

• 任务树操作、recalcUp 父子联动、今日可见性口径（纯 Rust 领域层重写，可复用 TS 逻辑设计）
• Snapshot v2 快照读写（原子写 + .bak.1~3 轮转）
• WebDAV 三方合并 LWW、墓碑传播、系统钥匙串存凭据
• GitHub Releases 更新检查、快捷键、窗口状态记忆

暂不做（明确范围外）

拖拽排序、搜索在 doit-desktop 中本就未实现，复刻版保持对齐，不额外新增；JS 扩展运行时（gpui-shell）非必需，暂不引入。

交付路线图（一次性成型）

1
骨架与设计系统
Cargo 工程、gpui-kit 初始化、把 tokens.css 全量翻译成 Theme 配置（亮/暗两套），跑通窗口与顶栏。
2
领域层与持久化
Rust 重写 types/taskTree/snapshot，原子写 + 备份轮转，先把数据层做稳。
3
今日页与核心交互
任务卡/子任务树、勾选与长按完成、右键菜单、原地编辑、快速添加——复刻 80% 体验。
4
统计 / 日历 / 设置
原生图表 + 自绘热力图、月历、设置面板与主题切换，完成全页面。
5
系统集成与同步
托盘/单实例/自启/窗口状态、WebDAV 三方合并、更新检查、通知。
6
测试与发版
gpui-kit UI 集成测试 + 领域单测，三平台 CI 打包，版本号与 doit 家族统一。

前置条件与风险

需本机 Rust 工具链与各平台系统依赖（macOS 已内置 font-kit 支持）。GPUI 生态年轻，个别组件细节可能需要读源码或自绘——已在「能做到」页逐项标注变通方案，无不可逾越障碍。

本原型为设计方案的可交互演示，最终以 Rust + gpui-kit 实现为准；视觉以本原型为 1:1 验收基准。
